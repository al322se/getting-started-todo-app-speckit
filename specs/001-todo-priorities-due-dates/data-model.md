# Data Model: Todo Priorities and Due Dates

## Entity: Task

Represents one todo item.

### Fields

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `id` | string | Yes | UUID generated by the backend. |
| `name` | string | Yes | Existing task title. |
| `completed` | boolean | Yes | Existing completion state. |
| `priority` | string or null | No | Valid persisted values: `high`, `medium`, `low`, or null. Null behaves as `medium`. |
| `dueDate` | string or null | No | ISO calendar date in `YYYY-MM-DD` format, or null when unset. |

### Validation Rules

- `priority` may be omitted or null.
- If provided, `priority` must be one of `high`, `medium`, or `low`.
- `dueDate` may be omitted, null, or an empty value that the backend normalizes to null.
- If provided, `dueDate` must be a valid calendar date in `YYYY-MM-DD` format.
- `completed` tasks are never marked overdue.
- Existing tasks without `priority` or `dueDate` must still load and edit successfully.

### Derived Values

- `effectivePriority`: `priority ?? 'medium'`.
- `isOverdue`: true only when `completed` is false, `dueDate` is set, and `dueDate` is before the current local calendar date.
- `priorityRank`: high before medium before low for ordering when due-date urgency is otherwise equal.

### Ordering Rules

The primary list orders tasks as follows:

1. Incomplete tasks before completed tasks.
2. Among incomplete tasks, overdue tasks first.
3. Earliest due date before later due date.
4. Tasks without a due date after dated tasks when priority is otherwise equal.
5. Higher effective priority before lower effective priority for tasks with the same due-date urgency.
6. Stable fallback ordering by existing list order or creation retrieval order.

## Persistence Shape

The existing `todo_items` table adds nullable columns:

| Column | Type | Notes |
|--------|------|-------|
| `priority` | varchar(10), nullable | Stores `high`, `medium`, `low`, or null. |
| `dueDate` | varchar(10), nullable | Stores `YYYY-MM-DD` or null. |

Implementation must add missing columns without dropping existing data in MySQL and SQLite.

## State Transitions

- Create task: starts incomplete and may include optional priority/due date.
- Edit task details: may add, change, or clear priority and due date.
- Complete task: keeps priority and due date but removes overdue display.
- Reopen task: overdue status recalculates from current date and due date.
